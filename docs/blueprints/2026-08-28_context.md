# Blueprint: Context

## 1. Executive decision

Build **Context**, an Ableton-first prompt-driven **co-producer**. While inserted on a track it holds the open set plus host-track audio/MIDI. The user steers it with a prompt, drop-in, reference, reverence, and abstraction. Later phases add loop-to-song staging, mix diagnostics, CLAP sample search, license-gated texture/transition synthesis, Demucs stems, and LOM writes of structure, automation, and colors. Preview stays read-only; Apply writes through the Live Object Model. See `docs/decisions/2026-08-28-context-coproducer-capabilities.md`.

Do not ship the original five-layer "all models in one plugin" stack. Cross-DAW VST3/AU is a later thin host that uses the same sidecar and drops stems plus MIDI. GarageBand will not receive project-level arrangement control.

MusicGen / CC-BY-NC weights stay out of the commercial path. Prompt UI is required (see `docs/decisions/2026-08-28-context-granular-intent.md`). Adapters remain license-gated.

## 2. Evidence and research method

Read-only research on 2026-08-28 using official Cycling '74 / Ableton pages, RNBO docs, license cards, and competitor public pages. Sources are listed in `docs/research/context-stack.md`. No market sizes or conversion rates were fabricated.

## 3. Intelligence report

Producers already have loops and sketches. Pain is turning that material into a structured 16–32 bar arrangement inside the open set. Current workarounds: Jukeblocks-style export/import, theory VSTs (Captain, Orb), chat-to-Live bridges (Producer Pal, VIXSOUND, LIA), or black-box song generators (Suno).

Repeated demand: editable output, in-session write, no royalty surprise, no second app round-trip.

## 4. User / problem definition

- Primary user: electronic or hybrid producer in Ableton Live 12 with Max for Live (Suite, or Standard plus add-on).
- Job: stay on a track, hear that track, see the rest of the set, and make the next granular edit from a prompt (add a bridge, expand a riff, add/remove a layer, add an effect, or match a reference).
- Outcome: previewed, undoable writes that feel like an instrument plus an effect, not a one-shot song generator.

## 5. Competitive landscape and gap

Direct: VIXSOUND, LIA, Producer Pal (Ableton assistants). Indirect: Captain, Scaler, Orb/LANDR Composer, Jukeblocks, Suno/Udio. Do-nothing: manual clip dragging.

Wedge: **in-session arrangement of the user's existing material**, not chat-to-MIDI and not a finished song. Live Object Model `create_audio_clip` / `create_midi_clip` is the Ableton-only advantage.

## 6. Unique value proposition

Context hears the track it sits on, knows the rest of the set, and takes the next step you prompt — including drop-in and reference-inspired edits.

## 7. Validation experiments and thresholds

1. LiveAPI harness: create one audio clip and one MIDI clip from fixtures in a test set. Pass = both clips exist at the requested times; undo restores the set.
2. Sidecar round-trip: fixture loop in, arrangement JSON out, schema valid. Pass = 100% schema validity on fixtures.
3. Producer smoke (later): five target users apply an arrangement to their own sketch. Pass = 3/5 keep at least one written section without reverting the whole write.

## 8. Product requirements

- C-1: Device loads as a frozen `.amxd` in Live 12 with Max for Live.
- C-2: Sidecar runs on localhost; device fails closed with a visible error if it is down.
- C-3: Analyze selected clips or referenced files for tempo, key, energy, and section candidates.
- C-4: Return an arrangement schema the device can preview before apply.
- C-5: Apply writes named clips and locators through LiveAPI. User can undo.
- C-6: Optional Demucs split of one mixed reference onto new audio tracks.
- C-7: No MusicGen / CC-BY-NC weights in the commercial path.
- C-8: No secret values in repo files.
- C-9: Cross-DAW host is out of V1; contract remains sidecar-compatible.
- C-10: Prompt field is required. Empty prompt cannot run.
- C-11: Device follows the host track (audio/MIDI in) and a `ProjectSnapshot` of the open set.
- C-12: Drop-in slot accepts a sample or loop for prompt-modify.
- C-13: Reference slot plus **reverence** (0–1) and **abstraction** (0–1).
- C-14: Scope, amount, wet, locks, focus, tempo/key lock, variation/replace, target section, audition vs apply.
- C-15: Loop-to-song staging from a 4- or 8-bar loop plus genre target into a ~3-minute section map.
- C-16: Key-matched transition/tension clips via a license-allowed adapter (not MusicGen/AudioLDM 2 commercially).
- C-17: Symbolic variation (humanize, ghost notes, counter-melody) on unlocked MIDI.
- C-18: Read-only frequency/masking audit across stems.
- C-19: Offline frequency-specific ducking/sidechain via pedalboard; Apply explicit.
- C-20: Optional untreated-room compensatory master-bus curve; Apply explicit.
- C-21: CLAP natural-language search over local sample folders.
- C-22: Texture synthesis via a legally reviewed adapter; pedalboard polish; Apply places the clip.
- C-23: Demucs stem split for rearrange/isolate.
- C-24: Populate Live (locators, automation, colors) via LOM. Export MIDI/stems for other DAWs. No `.als` write. dawdreamer is offline VST rehearsal only.

## 9. MVP scope and non-goals

V1 path: Ableton device as insert effect + LiveAPI writer, sidecar `IntentRequest` + arrangement plan, analysis, symbolic arrange, prompt/drop-in/reference chrome, then loop-to-song, mix audits, allowed generation, pedalboard, Demucs.

Later: RNBO/JUCE host, MIDI/stem export.

Excluded: unofficial `.als` write, MusicGen/AudioLDM 2 commercial weights, dawdreamer-as-DAW, FMOD/Wwise, Web Audio product, real-time generative accompaniment, AAX, claiming GarageBand arranges the project.

## 10. System architecture and data model

```text
Context.amxd (v8 LiveAPI + live.UI)
        |
   JSON / localhost
        |
context_sidecar
  analysis | symbolic | generation adapters | pedalboard
        |
   arrangement schema
        |
Ableton writer (LOM)     later: file-drop writer
```

Core entities: `IntentRequest`, `ProjectSnapshot`, `HostTrack`, `Knobs`, `ArrangementPlan`, `AnalysisReport`, `ApplyResult`. Retention: local only in V1. No cloud account.

## 11. Interfaces and integrations

- Sidecar HTTP: `GET /health`, `POST /analyze`, `POST /intent` (prompt + snapshot + knobs), `POST /arrange`, `POST /apply-plan` (plan only; Live write stays in the device).
- LiveAPI paths: `live_set`, `live_set tracks N`, `create_audio_clip`, `create_midi_clip`, locators.
- Formats: WAV/AIFF in, MIDI type 1 out, arrangement JSON.

## 12. Security, privacy, reliability, compliance

User audio never leaves the machine in V1. Generation adapters that call a network are off by default (`CONTEXT_ENABLE_GENERATION=0`). License gates in `docs/research/context-stack.md`. Plugin crash isolation: sidecar out-of-process. Fail closed if the sidecar is absent.

## 13. Delivery phase map

0 foundations → 1 LiveAPI harness → 2 analysis/symbolic + mix audits → 3 Ableton writer (loop-to-song, automation, colors) → 4 generation + CLAP + Demucs → 5 pedalboard + room curve + dawdreamer rehearsal → 6 cross-DAW MIDI/stem host → 7 harden and owner handoff.

## 14. Cultural go-to-market

First audience: Max for Live and Ableton producer forums, r/ableton, r/MaxForLive. Lead with a useful free fixture or arrangement-schema spec. No astroturfing. Claims must match verified behavior (no "works in GarageBand as an arranger").

Reddit hook concepts (not for posting now):

1. Problem-first: "How do you turn a 4-bar loop into a 32-bar arrangement without leaving Live?"
2. Build journey: LOM clip-create limits and why `.als` write was rejected.
3. Resource: publish the arrangement JSON schema.

## 15. Risks, pivots, and no-build criteria

- LiveAPI clip-create edge cases (frozen tracks, record-enabled tracks).
- Max for Live audience is Suite-weighted.
- License mistakes on generative weights.
- Name collision with this repository and other "Context" products.

No-build if LOM cannot create clips in current Live 12.x on the owner's machine (phase 1 gate).
